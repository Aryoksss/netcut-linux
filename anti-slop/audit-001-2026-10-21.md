# Audit antislop 001, 2026-10-21

Mode: AFTER, run on the dashboard redesign shipped as v1.3.0.
Scope: `webgui.py` (PAGE: HTML, CSS, JS) plus the direction file `DESIGN.md`.
Method: each finding cites the rule it violates and one line on why it matters.
Priority follows the tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Lock = LOW.

Result of the run: no HIGH findings. The redesign removed the previous set of tells
(five equal KPI cards, glowing status dot, uppercase tracked headers, pill chips,
10px radius and shadow on every surface, empty sub-labels). What remains is listed
below, ordered by what a reviewer would notice first.

---

## MEDIUM (Purpose-Gate: technique present, reason thin)

**1. Icon set is one library voice.**
Rule: R-04. Every glyph (wifi, ban, host, scan, list, alert) is the same thin-stroke
rounded family, so the set reads as an import rather than a decision. Each icon is
relevant to its label, which is why this is not HIGH, but the product has no glyph
of its own. Fix: replace two or three key glyphs (the brand mark, the block action)
with something drawn for this tool.

**2. The brand has no typographic voice.**
Rule: R-06, R-20. Identity currently rests on density, the status rail, and the answer
line; the typeface is the system sans. That is defensible for a desktop tool, but it
means swapping the wordmark would leave the screen looking like any competent ops UI.
Fix: one deliberate display decision (a narrower face for the answer line, or a
distinct tabular face for quantities) would give it a voice without decoration.

## LOW (Quality Locks)

**3. Status cell fits two badges, not three.**
Rule: R-05. At 200px the cell holds "limit 512kbit" plus "peringatan". A row that is
both limited and spoof-flagged and carries a note would overflow into the actions
column. Fix: cap the cell at two badges and move the rest into the row tooltip.

**4. Truncated device names have no visible affordance.**
Rule: R-27, C-4. Long vendor strings clip with an ellipsis and the full value lives in
`title`, which a touch user cannot reach. Fix: a row detail dialog (click the device
cell already opens the rename dialog; the full string belongs there).

**5. Unlimit is an icon-only control.**
Rule: R-26. The "×" button carries `title` and `aria-label`, so it is operable and
named for assistive tech, but visually it is the smallest target in the row. Fix: text
label at wide breakpoints, icon below 900px.

**6. One concept, three words.**
Rule: R-16, R-31. The same idea appears as "Limit" (button), "Dibatasi" (filter and
stat) and "limit 512kbit" (badge). Each is defensible alone; together they make the
reader translate. Fix: pick one noun and use it in all three places.

**7. Two totals, one screen.**
Rule: R-17. The strip shows interface totals (Unduh/Unggah) while the table footer
shows the sum of the visible rows. Both are real and labelled, but the difference is
only explained in a tooltip. Fix: name the strip "interface" explicitly, or show the
row sum there too.

**8. Demo fixture data looks like a fixture.**
Rule: R-38 (applies to shipped content, not tests). `tools/ui_test.py` uses sequential
MACs (`aa:bb:cc:dd:ee:01`); that is fine for tests, and the README screenshots come
from a different fixture with realistic values. No action needed unless the test
fixture is ever reused as a screenshot source.

## What was checked and passed

- R-02: zero em dashes in UI text, tray labels, README, DESIGN.md, and the diagram
  sources (verified by grep; the mermaid blocks were re-synced after the change).
- R-25: every text token measured against the surface it sits on. Dark minimum 5.2:1,
  light minimum 4.71:1.
- R-03: no horizontal overflow at 420px (`scrollWidth == innerWidth`).
- R-32: focus-visible outline on every control, Esc closes the dialog, keyboard
  shortcuts documented and bound.
- R-27: empty state names the cause and offers Scan ARP; loading says "memuat"; error
  path distinguishes "scan gagal" from "0 host"; the answer line reports data age.
- R-33: no patch scripts; the theme is two token blocks, not a string rewrite.
- R-34: both themes verified in screenshots, tokens measured in both.
- R-35: 44 UI tests pass, click-through covered by the test suite (sort, filter,
  search, select, bulk bar, modal, theme, pause, shortcuts).
- R-17, R-18, R-36, R-38: every number on screen comes from the live snapshot; no
  invented metrics, no testimonials, no claims.
